# Data-source inventory

Phase 0 deliverable 6. Draft of 21 Oct 2026, revised 22 Oct 2026 (Phase 0 review, then D-023 and the MF Screener data
pack) and 22 Oct 2026 (the owner's answers: D-026 for the Screener pack, D-032 for capital-gains statements, the Index
TRI files as the index data; change log at the end of `open-questions.md`). Merged from the data-source investigation [DS], the MF Screener
audit [SC], the engine inventory's reference-data section [IE §8] and the previous owner's records [PO §4]. Every
source the legacy or the new application reads, with its producer, cadence, identifiers, consumers, ingestion path
(today and new), gaps, publication class and **public-repository eligibility**.

**Publication after D-023 (22 Oct 2026).** The vendor licence allows publishing every Accord Fintech file (the
monitors and, later the same day, every other Accord file, both on 22 Oct 2026). The approved
monthly source files (MF Monitor, SIF Monitor, Investment Reckoner, PMS and AIF one-pagers, market update slides,
disclaimer, index data) are tracked publicly in `monthly_updates/YYYY-MM/`; files above 50 MB (for example the
Investment Reckoner PPTX) are tracked as PDF, with the original kept in private storage and its SHA-256 recorded. The
vendor-derived data embedded in the page is permitted (the D-008 question is closed). Client data is never published.
The MF Screener data pack is never published or embedded in a public build: the owner uploads it into the app every
cycle and the browser keeps it (D-026).

**Publication classes** [DS "Publication classes", updated for D-023]
- **P** publishable: every Accord Fintech file (the owner confirmed on 22 Oct 2026 that the licence covers all Accord
  files, D-026), another approved monthly source file under D-023 point 1, or Centricity-owned material with no client
  or personal data. Committed after the privacy scan.
- **C** private until approved: a source D-023 does not name, or one whose owner has not agreed. Its derived data may
  be embedded where D-023 permits it; the raw file stays in private storage, proven by SHA-256.
- **N** never publish: client data, personal data, credentials, confidential client presentations, the MF Screener
  data pack (D-026).

**Public-repository eligibility**
- **Yes**: the file is committed in `monthly_updates/YYYY-MM/` after the privacy scan (class P).
- **Yes, as PDF**: a file above 50 MB is committed as PDF; the original's SHA-256 is in the manifest (D-023).
- **Derived only**: the raw file is never committed (proceeding on default until its role is approved); data derived
  from it is embedded in the public build, as the legacy page already does (permitted by D-023).
- **Browser only**: never committed and never embedded; uploaded into the app's slot and kept in that browser's
  IndexedDB until a newer cycle is loaded; only its fingerprint and counts are published (the Screener pack, D-026).
- **Never**: class N; quarantined and reported if found in a monthly folder.

**Evidence tags:** V verified by the investigator (file opened read-only, code read or script run); D documented, not
re-checked; I inference; U unknown.

## 8. Freshness rules (STALE DATA)

Defaults, configurable in `data/owner/freshness.json`; a value past its limit is shown with its date and the STALE DATA
status, never silently.

| Role | Stale when older than |
|---|---|
| MF and SIF Monitor, analytics, listed equity | 45 days before the review's as-on date |
| Expense ratio per key | last seen more than 3 monthly files ago |
| In-house risk ratios | 45 days |
| Screener pack (scores, ranks, risk, returns, prices, holdings) | one cycle (scores and ranks shown up to three cycles, then suppressed, Q-21); a pack's prices and holdings are used only for the month-ends they carry |
| Index data | 45 days before the review's as-on date for the latest point; history never stale |
| PMS and AIF performance, PMS/AIF look-through | one quarter |

| Product-bank card fields | 6 months from the card's as-on |

## 9. Classification rules and the monthly folder

The update engine classifies by content signature, then structure, then name (a disagreement stops that file); the
full rule table is [DS §9] and becomes `monthly_updates/_policy/classification-rules.json` in M11. Two roles are added:
`screener_pack` (a zip whose `manifest.json` names contract `pr-datapack-v1`; class N, never copied into the
repository) and `index_data` (class P). Fingerprint = SHA-256 + role + data month; identical fingerprints are no-ops;
two fingerprints for one role and month are competing files; a byte-identical copy of last month's file is a stale
copy. Client material (headers with client, folio, PAN, units with invested and market value; PAN pattern; e-mail or
phone patterns; a deck titled "Portfolio Review") is class N and is quarantined. Folder layout and what is tracked:
`09-repository-and-docs-structure.md` §5.

## 10. Product bank fields and their sources

Schema and per-field provenance: [DS §10] and `03-architecture.md` §12. What the Reckoner and one-pagers can supply:
names, product type, Centricity section, structure, terms, fees, house flags, objective, managers, benchmark name (from
chart series), performance by period with period and return basis, top holdings and sectors (always PARTIAL COVERAGE).
What they cannot supply (left as statuses or filled from elsewhere): ISIN, AMFI code (from the crosswalk and the
Screener pack), SEBI registration, risk-o-meter, SEBI category for PMS/AIF, NAV and units, full holdings, TER for
PMS/AIF.
