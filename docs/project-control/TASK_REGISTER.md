# Task register

Last verified: **28 Oct 2026 (IST)**, by MOD-01 for the MOD-01 to MOD-02 handover. Maintained by **MOD-02**.

Every piece of work has one stable task id. Repeated requests update the existing task; they never create a duplicate.
- **TA-nn**: Workstream A, the existing dashboard (the live `index.html`).
- **TB-nn**: Workstream B, the new build (CR-0006, `/next/`).
- **TC-nn**: coordination, governance and handover.

The audit's "batches 2 to 7" are not the fix batches: fix batch 1a + 1b is audit batch 1 (TA-01); fix batches 2a, 3 (tax) and 4
(base file) are TA-02, TA-03 and TA-04; audit batches 2 to 7 are TA-12..TA-17.

Defects keep their KI ids in [docs/KNOWN_ISSUES.md](../KNOWN_ISSUES.md), decisions their D ids in [docs/DECISIONS.md](../DECISIONS.md),
change requests their CR ids in [docs/change-requests/README.md](../change-requests/README.md). This register links to them and does not
restate them. Active branches and files in flight are in [ACTIVE_CHANGE_REGISTER.md](ACTIVE_CHANGE_REGISTER.md); chats in
[CHAT_REGISTRY.md](CHAT_REGISTRY.md). "PD-nn" is a pending owner decision in the decision log of this folder.

**Status words** (the owner's nine): VERIFIED COMPLETE; IMPLEMENTED, NOT FULLY VERIFIED; IN PROGRESS; PLANNED; BLOCKED; NOT STARTED;
EXISTING DEFECT; UNKNOWN / NEEDS INVESTIGATION; SUPERSEDED.
**Evidence labels:** [VERIFIED] (with the evidence), [INFERRED], [UNCERTAIN], [UNKNOWN].

**Merge order is a readiness rule, not a fixed order** (lead decision of 28 Oct): whichever change passes Gates A to D first merges
first; the second takes main, keeps DECISIONS in number order and keeps both sides' rows in CHANGELOG, PROJECT_STATE, KNOWN_ISSUES and
TESTING. Exceptions are written in each task's dependencies (TA-05 after TA-03; TA-03 after the owner's Q17/Q18 answers or acceptance of
the safe defaults). Details: [FILE_OWNERSHIP_AND_CHANGE_CONTROL.md](FILE_OWNERSHIP_AND_CHANGE_CONTROL.md#merge-readiness-rule).

**Standard acceptance (Gates A to E).** Unless a task says otherwise, "accept when" means: Gate A implementation report; Gate B ARC-01
GO plus the domain reviews the change needs (financial-domain-reviewer for any calculation or tax rule; security-release-reviewer GO
before every push and PR); Gate C the full check list of [docs/TESTING.md](../TESTING.md) actually run, browser acceptance by
qa-engineer for anything visible, Office checks for PPTX/XLSX changes; Gate D PR, green CI, D-020 merge, Pages verified; Gate E owner
acceptance for user-visible behaviour. Each gate is recorded in [INTEGRATION_AND_REGRESSION_LOG.md](INTEGRATION_AND_REGRESSION_LOG.md).
